# 0.1.1 自动检测修复

用户报告手动锁定有效、自动防护不触发。本机原生输入测试重现了相同行为。

## 原因

启动代码读取 `GetAsyncKeyState` 后调用 `SeedHeld`，把 Windows 的逻辑按键状态同时写入物理按住集合。该集合又决定是否仍在等待旧按键全部松开。本机测试在未输入时就读到两个残留状态 `0x24` 和 `0x63`，没有对应的松开事件，导致 `drain` 一直为真，所有自动检测都被跳过。

旧测试直接创建空状态的检测器，漏掉了这一真实初始化路径。启动检查只确认钩子句柄非零，同样不能发现这个问题。

此外，上游规则把 Ctrl/Alt 按住时的所有其他按键都排除，猫踩压混入修饰键也会绕过检测。

## 修复

- 启动时仅保留已放行按键的松开配对，不从逻辑状态推断物理按住状态；物理按住状态只由钩子实际收到的事件维护。
- 修饰键本身不计入猫踩压评分，但不再屏蔽其他键的检测。Ctrl+C 等少量按键的持续快捷键仍不触发。
- 主界面显示输入事件数、当前按住键数和拦截数，便于确认防护是否实际收到输入。
- 增加启动残留状态、Ctrl/Alt 踩压和普通快捷键回归断言，共 61 项。
- 增加真实 Windows 钩子与接收窗口的本机输入验收程序，分别提供模拟输入链路测试和实体键盘验收。

## 验证边界

修复前本机输入链路测试中，手动锁定成功，但自动锁定失败；修复后同一测试全部通过，并确认自动锁定后接收窗口收不到后续测试输入，松开后恢复。此项使用测试标记的 SendInput 事件，不等同于实体键盘验收。

实体键盘验收已通过，记录见 [实机验收](实机验收.md)。游戏、特殊布局、远程桌面及输入法的完整兼容性不在这些测试结论中。
