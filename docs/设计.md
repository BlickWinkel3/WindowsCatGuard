# Windows 防猫踩键盘工具设计

目标是一个 Windows 10/11 x64 托盘小工具：猫踩键盘时暂停输入，用户能随时恢复。采用 **CatSit 的 C# 与 WPF 实现作为底座，借鉴 PawPause 的简洁交互和猫离开后自动恢复方式**。

## 首版功能

- **手动锁键**：托盘按钮或 `Ctrl+Alt+L` 切换，适合提前发现猫靠近、擦键盘等场景；保持锁定直到人工解锁。
- **自动防护**：检测邻近多键同时按下、短时间乱按、多键持续压住；提供 1–10 档灵敏度和“仅提示”试用模式。
- **自动恢复**：自动触发后，全部物理按键（含修饰键）松开且连续安静 1 秒，再恢复输入；可切换为“保持锁定”。这里将松键也计入活动，比 PawPause 原实现更保守。
- **清晰反馈**：托盘显示关闭、监测、锁定三种状态；锁定时显示不抢焦点的小猫提示和解锁说明，声音可关闭。
- **人工出口**：锁定期间优先识别 `Ctrl+Alt+L`，也可用鼠标点击托盘解锁。首版默认只锁键盘，保留鼠标；开机启动为可选项。

## Windows 实现思路

沿用 CatSit 的 **.NET 10、WPF、WinForms NotifyIcon**，发布自包含便携 EXE。纯检测与状态机放在 Core 层，Windows 输入处理放在 Interop 层，托盘和提示窗只负责显示、设置与操作。

输入流程为：**键盘钩子 → 更新物理按键状态 → 优先处理解锁 → 检测及锁定状态判断 → 放行或屏蔽事件**。检测和屏蔽决定在钩子线程内完成，限定时间窗与缓存大小；界面、声音和文件写入异步执行，避免等待 UI 才生效。Windows 允许低级键盘钩子返回非零值阻止事件继续传递，但回调超时可能导致钩子被静默移除，因此回调必须短小。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)

状态分为关闭、监测、自动锁定、手动锁定。物理按键集合独立于检测器，锁定后仍处理松键；解锁清空检测窗口，并等待旧按键全部释放后再接受新的检测序列，避免立即重锁。

另记录哪些按下事件已放行：它们的松开事件须正确送达；锁定中被屏蔽的按下事件，其松开也应配对处理。人工解锁组合键同样处理配对，避免 Ctrl、Alt 或普通键残留。PawPause 源码中锁定状态的 Esc 实际会被消费后解锁，Windows 版采用组合键并明确这一行为。

暂停和退出时卸载钩子；安装失败需回收已创建的资源并显示“防护未启用”。`Ctrl+Alt+Delete` 是 Windows 保留的安全序列，可进入系统界面处理故障，不能把它当作程序自身已解锁的保证。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/security/identity-protection/smart-cards/smart-card-architecture)

## 边界与验收

自动检测达到阈值前，少量输入可能已经进入前台应用；不自动删除或重放这些输入。需要预先阻止输入时使用手动锁定。管理员窗口、远程桌面、特殊键盘布局和采用特殊输入路径的游戏列为兼容性实测项，首版面向本地普通桌面应用。

默认离线，只保存设置和触发原因等统计信息，不保存输入文本。验收先覆盖正常中文输入、快捷键、长按和游戏组合键，再模拟邻键乱按、持续压键，检查检测、自动恢复及人工解锁；重点检查跨锁定边界的按下与松开配对，以及暂停、退出、钩子失败后的输入恢复。先完成手动锁定与可靠解锁，再接入自动检测，最后加托盘设置和猫提示。
